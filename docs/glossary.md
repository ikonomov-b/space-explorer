# Glossary

Reviewed 2026-09-08. Normative terminology for the project documents ([decision 0006](decisions/0006-pack-identity-and-allocation.md)). Entries marked *proposed* come from the [design review](review.md) and become definitive when the corresponding finding is cleared.

## Content identity

| Term | Definition | Source |
| --- | --- | --- |
| Primitive definition | A typed reusable building block with a category, composition domains, engine-neutral geometry, surface references, parameter schema, connectors, constraints, dependencies, and provenance. Identity is `(pack_id, primitive_id)`; exact content is identified by its content-hash revision. | [Registry](technical-design.md#primitive-registry-and-composition), [decision 0031](decisions/0031-primitive-complete-composition-and-storage.md) |
| Exact primitive reference | A `PrimitiveId` plus its definition content hash. Dependencies, reference tables, and composition nodes use this pair. A generated definition has one revision for life, so the hash verifies that the loaded content is the referenced content; for an authored template it distinguishes revisions. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0033](decisions/0033-generated-definitions-have-one-revision.md) |
| Primitive instance | One occurrence of an exact primitive revision in a composition graph, with a deterministic hierarchical path, generated parameters, transforms, and connector edges. Repeated instances may use the same definition. Explicit instances are stored nodes; derived instances are not. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0038](decisions/0038-derived-instances.md) |
| Derived instance | An instance a deriving category's recipe produces from a node's parameters and stream, addressed as `<node path>/item/<index>`, not stored as a node, counted against the node's declared derived budget, and a valid overlay target. | [Decision 0038](decisions/0038-derived-instances.md) |
| Primitive category | A stable numeric entry in the category registry that defines a primitive's parameter schema, permitted domains, connector kinds, storage-policy options, validation limits, and permitted generator revision identifiers. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0035](decisions/0035-category-registry-record-and-generator-revision-identifiers.md) |
| Category registry | The canonical record `category-registry/N` that defines every primitive category for revision `N`, shipped as authored data and identified by its content hash. A definition record's domain label carries the revision it is laid out under; pack manifests pin the revision and hash. | [Decision 0035](decisions/0035-category-registry-record-and-generator-revision-identifiers.md) |
| Generator revision identifier | A stream path `<generator>/<k>` naming one retained implementation of a `regenerate` or `hybrid` recipe, listed per category by the category registry, named by the definitions it produces, and pinned by set and world manifests. Distinct from the generator version. | [Decision 0035](decisions/0035-category-registry-record-and-generator-revision-identifiers.md) |
| Composition domain | A broad context such as solar system, planet, surface, cave, life form, site, or artifact in which a primitive may participate. A primitive may allow several domains; typed connectors decide whether particular instances can combine. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md) |
| Pack | A namespace for primitive definitions identified by a 128-bit `pack_id`. An authored pack has revisions and an append-only allocation ledger; a generated pack is published once per set-generation run with IDs 1..n and its identifier derived from the set specification. | [Registry](technical-design.md#primitive-registry-and-composition), [decision 0006](decisions/0006-pack-identity-and-allocation.md) |
| Pack revision | A snapshot of a pack's definitions and their content hashes. Revisions of one pack share the allocation ledger; only authored packs have more than one. | [Registry](technical-design.md#primitive-registry-and-composition), [decision 0033](decisions/0033-generated-definitions-have-one-revision.md) |
| Allocation ledger | The append-only record of IDs allocated within an authored pack. IDs are never recycled; zero is reserved. Generated packs need no ledger. | [Registry](technical-design.md#primitive-registry-and-composition) |
| Template / vocabulary | An authored parametric rule from which primitive definitions are generated. The vocabulary is the set of templates plus their constraints. | [Concept 8](concept.md#8-randomness-from-expandable-primitives) |
| Biome rule set | A template vocabulary scoped to the `biome element` primitive category: an authored set of parametric rules and constraints generating biome-element primitives, giving a region's environmental profile a distinct character. The core release requires at least three. | [Primitive registry](technical-design.md#primitive-registry-and-composition), [decision 0026](decisions/0026-biome-rule-sets-and-recovery-challenges-are-template-vocabularies.md) |
| Recovery challenge | A template vocabulary scoped to the `site component` category and constrained to the return-path site type: an authored obstacle and route combination a player actively navigates between an artifact site and the ship, covering the "route and challenge" that valuation scores as recovery effort. The core release requires at least two. | [Artifact valuation](technical-design.md#artifact-valuation-and-transactions), [decision 0026](decisions/0026-biome-rule-sets-and-recovery-challenges-are-template-vocabularies.md) |
| Primitive set | An immutable, validated catalogue of exact primitive revisions plus composition rules and dependencies. The first stored construction unit; identified by its manifest hash, and exactly one manifest exists per `pack_id`. It is distinct from the ordered composition graphs built from its definitions. | [Sets](technical-design.md#primitive-sets-and-compact-references), [decision 0039](decisions/0039-one-manifest-per-pack-identifier.md) |
| Set manifest | The record identifying a set: generation specification, accepted definitions, membership or reference table, exact dependencies, provenance, and validation result. | [Persistence](technical-design.md#persistence-and-compatibility) |
| Package | An immutable on-disk bundle with a manifest and data files. Either a set package or a world package. | [Decision 0006](decisions/0006-pack-identity-and-allocation.md) |
| Handle | A package-local unsigned index into that package's immutable table of exact primitive references. Not an identity; tables cannot be reordered in place. | [Sets](technical-design.md#primitive-sets-and-compact-references) |
| Storage policy | A category's choice of `regenerate`, `materialize`, or `hybrid`, pinned per category by the world manifest, and by the set manifest for set-owned payloads, at generation time from versioned measured configuration; the category registry lists the permitted options and no definition carries a policy. Materialized output remains owned by the primitive instance. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0034](decisions/0034-storage-policy-pinned-by-manifests.md) |
| Primitive state overlay | Mutable state records keyed by stable explicit or derived instance path and expressed as state primitive IDs plus parameters. Applied over an immutable generated base graph for discoveries, collection, damage, depletion, and similar changes. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md) |
| Content hash | A specified hash such as SHA-256 over a canonical binary encoding. Never a runtime object hash. | [Determinism](technical-design.md#destination-identity-and-determinism) |
| Generator version | The integer identifying the frozen set of authoritative generation algorithms: the SHA-256 stream derivation, PCG32 initialisation and output, bounded sampling, and the stream-path grammar. Manifests pin it, and changing any frozen algorithm increments it. Currently 2. Generator revision identifiers name the separate recipe implementations. | [Decision 0008](decisions/0008-random-stream-derivation.md), [decision 0021](decisions/0021-sha256-stream-derivation.md) |
| Stream path | The stable canonical path, such as `system/planet/0/region/3/artifact/2`, that addresses one random stream within a world and forms part of an artifact's identity. Segments are non-empty runs of `[A-Za-z0-9_-]` joined by `/`, case-sensitive, encoded as UTF-8. | [Decision 0008](decisions/0008-random-stream-derivation.md), [decision 0019](decisions/0019-generator-version-1-frozen.md) |

## Worlds and destinations

| Term | Definition | Source |
| --- | --- | --- |
| Destination specification | Campaign branch ID, seed, distance tier, fixed content budget, and pinned versions of generator, registry, grammar, suit profiles, and valuation rules; environment preferences and survey focus are not core fields. Its content hash identifies the world within its campaign. | [Determinism](technical-design.md#destination-identity-and-determinism), [decision 0007](decisions/0007-artifact-collision-substitution-and-campaign-salt.md), [decision 0043](decisions/0043-destination-controls-distance-tier-and-seed-lever.md) |
| World | A destination generated from a specification. Pins set manifests and a grammar revision. Lives in its discoverer's campaign and is visited only in a session that discoverer hosts. | [Composition validation](technical-design.md#composition-validation) |
| World package | The immutable specification, accepted descriptors, pinned dependencies, and region data of a world. | [Architecture](technical-design.md#architecture-and-ownership) |
| World manifest | The manifest of a world package: specification identity, seed and inputs, pinned versions, accepted descriptors, dependency hashes, and validation result. | [Persistence](technical-design.md#persistence-and-compatibility) |
| Generation job | The durable record of one destination's preparation: specification, reserved charge, completed tasks, checkpoints, progress, and failure state. Stages are draft, reserved, generating, validating, ready. | [Lifecycle](technical-design.md#generation-lifecycle) |
| Region | A bounded landing area of at most 2,048 m per axis represented by a deterministic spatial subgraph/chunk of a planet's complete primitive composition, flat on the tangent plane of its surface anchor, on a body of reference radius at least 524,288 m. Terrain, placements, sites, environment, and completion derive from exact primitive revisions, parameters, primitive-owned payloads, and state overlays. Positions are region-local fixed-point integers. | [Persistence](technical-design.md#persistence-and-compatibility), [decision 0010](decisions/0010-units-coordinates-and-region-bounds.md), [decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0041](decisions/0041-planet-fields-tangent-regions-minimum-radius-and-far-field.md) |
| Astronomical state | The pinned system inertial frame and epoch, saved simulation time, body and orbit parameters, planet-fixed rotation state, and region-to-planet mapping from which observer-centred celestial results are derived. Godot does not own this state. | [Surface sky](technical-design.md#astronomical-state-and-surface-sky), [decision 0032](decisions/0032-astronomically-consistent-surface-sky.md) |
| Surface anchor | The connector that attaches a region to a planet: latitude, longitude, height above the reference radius, and heading clockwise from north, which together define the region-local tangent frame. | [Units](technical-design.md#units-coordinates-and-bounds), [decision 0036](decisions/0036-frames-and-transforms-typed-by-connector-kind.md) |
| Binary turn | The authoritative angle type: a signed 32-bit value over 2^32 turn, range ±half a turn, resolution about 1.46 × 10^-9 rad. | [Decision 0036](decisions/0036-frames-and-transforms-typed-by-connector-kind.md) |
| Derivation rule | A primitive named by a generator revision identifier `derive-<name>/<k>` that computes one physical quantity from parameters referenced by instance path with an integer or fixed-point implementation and recorded vectors; used where an aggregation rule would be. | [Decision 0037](decisions/0037-derivation-rules-integer-periods-and-orbit-hierarchy.md) |
| Barycentre | A non-rendered primitive that an orbit connector may name as parent, with the aggregated mass of its children; the root of a binary system. | [Decision 0037](decisions/0037-derivation-rules-integer-periods-and-orbit-hierarchy.md) |
| Far field | The ground rendered between a region's edge and the geometric horizon, derived by the adapter from the planet's cube-sphere relief grid in the region's tangent frame as an evictable cache; no collision, placements, or state. | [Decision 0041](decisions/0041-planet-fields-tangent-regions-minimum-radius-and-far-field.md) |
| Cube-sphere grid | The planet-domain bounded grid: six square faces at a declared power-of-two resolution, a cell addressed by face, `u`, and `v`, oriented in the planet-fixed frame as the category registry fixes. | [Decision 0041](decisions/0041-planet-fields-tangent-regions-minimum-radius-and-far-field.md) |
| Surface sky | The observer-centred result derived from astronomical state: local directions, distances, angular sizes, phases, horizon visibility, eclipses, occultations, star lighting, background stars, and atmosphere effects visible from a planet's surface. | [Decision 0032](decisions/0032-astronomically-consistent-surface-sky.md) |
| Site | A located point of interest within a region: an artifact site, hazard, observation point, or return path node. | [Lifecycle](technical-design.md#generation-lifecycle) |
| Composition graph | A bounded, ordered, acyclic graph of primitive instances, parameters, transforms, connectors, and child edges that completely represents a solar system, planet, surface, cave, life form, site, or artifact. Not deduplicated set membership. | [Sets](technical-design.md#primitive-sets-and-compact-references), [decision 0031](decisions/0031-primitive-complete-composition-and-storage.md) |
| Composition grammar | The versioned canonical record that decides how a graph is built: the depth, instance, and retry bounds, the weighted root categories per composition domain, and per connector kind a child-count range, the eligible weighted categories, and the range an attachment transform is drawn from. Identified by its content hash, which every graph specification pins; tuning any of it is a new grammar version. Version 1 is defined in code over registry revision 1. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0048](decisions/0048-composition-grammar-version-1-graph-records-and-graph-publication.md) |
| Instance path | The stable canonical path that addresses an instance's random stream, state overlay, cross-chunk references, and cache entries: the composition domain's label at the root, then `<parent path>/<connector label>/<index>` for each child. It is not an allocated primitive ID. | [Decision 0031](decisions/0031-primitive-complete-composition-and-storage.md), [decision 0048](decisions/0048-composition-grammar-version-1-graph-records-and-graph-publication.md) |
| Chunk | A deterministic spatial partition of a composition graph. Every instance has one owning chunk, generating one chunk never consumes another's random stream, cross-chunk edges use stable instance paths, the world manifest indexes chunks, and chunk identity keys the evictable caches. Dimensions and the form of the identity are fixed at M0b ([open items](progress.md#open-items-outside-the-plans-process)). | [Region encoding](technical-design.md#region-encoding-and-compression), [decision 0031](decisions/0031-primitive-complete-composition-and-storage.md) |
| Appearance recipe | The canonicalized composition recipe of an artifact used for uniqueness comparison, excluding instance IDs, names, invisible metadata, and irrelevant ordering. | [Composition validation](technical-design.md#composition-validation) |
| Variation overlay | The list in a world manifest of artifact path and variation index for substitutions applied at generation to avoid appearance collisions with the campaign's existing artifacts. | [Decision 0007](decisions/0007-artifact-collision-substitution-and-campaign-salt.md) |
| Distance tier | A discrete access level from the home anchor that sets content budget, reward range, recovery demands, and the planet and region counts, shown on the dashboard as a light-year label. The core has two tiers: the starter tier guarantees one explorable planet and no life, the second at least two explorable planets and a life-bearing one. | [Scope](development-plan.md#scope-and-working-assumptions), [decision 0043](decisions/0043-destination-controls-distance-tier-and-seed-lever.md), [decision 0044](decisions/0044-tiered-system-composition-one-star-and-explorability-by-validation.md) |
| Home anchor | The fixed location for trading and progression from which distance is measured and every expedition departs and returns. | [Scope](development-plan.md#scope-and-working-assumptions) |
| Seed lever | The dashboard control that fills the specification's 64-bit seed with a fresh near-unique value, shown to the player only as an abstract cue and never typed back. Not a salt: that word names the campaign branch mixed in by decision 0007. | [Decision 0043](decisions/0043-destination-controls-distance-tier-and-seed-lever.md), [decision 0021](decisions/0021-sha256-stream-derivation.md) |
| Explorable planet | A planet on which at least one region passes suit-profile validation on a body of reference radius at least 524,288 m. A validation outcome, never a body-type label. | [Decision 0044](decisions/0044-tiered-system-composition-one-star-and-explorability-by-validation.md), [decision 0041](decisions/0041-planet-fields-tangent-regions-minimum-radius-and-far-field.md) |
| System description | Text derived on demand from a world's accepted graph: the star's spectral class and each planet's body type, explorability, and life, with counts. Printed by the command-line tool from M0b and shown on arrival from M1; never stored. | [Decision 0045](decisions/0045-close-views-only-in-the-surface-sky-and-a-derived-system-description.md) |
| Generation iteration | One numbered round of the solar-system generator: pinned registry revision, vocabulary hash, grammar version, and seed list; one system per seed; every system's derived description checked against its tier's rules and read by the owner; verdict and next change recorded in progress. | [Decision 0047](decisions/0047-usable-storage-and-structure-generation-then-solar-system-iterations.md) |

## Campaign and play

| Term | Definition | Source |
| --- | --- | --- |
| Campaign | The host-owned save holding branch ID, players, permissions, credits, upgrades, inventory, catalogue, and destination index. | [Persistence](technical-design.md#persistence-and-compatibility) |
| Branch | The identity of one campaign's history. Forking assigns a new branch ID; branches never exchange inventories. | [Determinism](technical-design.md#destination-identity-and-determinism) |
| Artifact (instance) | A located, collectable object with a stable ID, origin, appearance graph, physical properties, valuation inputs, and predefined value, bounded at 2 m in every axis, with a mass summed from its parts and a size class from its bounds. Distinct from the primitive definitions it is composed from. | [Persistence](technical-design.md#persistence-and-compatibility), [decision 0046](decisions/0046-artifact-families-human-height-cap-cargo-by-mass-and-material-rarity.md) |
| Reference effort | The fixed, versioned effort scores for generation and recovery from which an artifact's base value is computed. Independent of wall-clock time. | [Valuation](technical-design.md#artifact-valuation-and-transactions) |
| Field cache | The recoverable store of carried artifacts left behind when a player's suit reserves are exhausted. | [Core-release contents](development-plan.md#core-release-contents) |
| Command | A uniquely identified request validated by the authority against location, reachability, capacity, ownership, permission, price, and state revision. Retries return the original result. | [Valuation](technical-design.md#artifact-valuation-and-transactions) |
| Host | The player whose machine owns the campaign save and performs all simulation and generation compute for a session. | [Decision 0003](decisions/0003-network-topology-and-transport.md) |
| Guest | An invited player whose avatar, inventory, and progress live in the host's campaign. The core release supports one; the session model supports more up to host capacity. | [Decision 0003](decisions/0003-network-topology-and-transport.md) |
| Coordination server | A simple cloud service providing directory, invitation, presence, and relay or NAT-traversal assistance for hosts. Holds no campaign state and computes no worlds. | [Decision 0003](decisions/0003-network-topology-and-transport.md) |
| Tick | The host's fixed simulation step of 50 ms (20 Hz) in which hazards are applied and commands validated; durations are counted in ticks. | [Decision 0010](decisions/0010-units-coordinates-and-region-bounds.md) |
| State revision | The monotonically increasing version of committed campaign state used for optimistic command validation and resynchronization. | [Multiplayer](technical-design.md#multiplayer-and-trust-boundary) |
| Transaction ledger | The append-only, tag-chained list of committed commands from which credits and custody are derived; cached totals are never the only copy. | [Save integrity](technical-design.md#save-integrity), [decision 0018](decisions/0018-data-root-region-encoding-and-save-integrity.md) |
| Modified campaign | A campaign whose ledger chain, record tags, or load-time invariants failed verification. Disclosed to the host and to guests at join; never a lockout. | [Save integrity](technical-design.md#save-integrity), [decision 0018](decisions/0018-data-root-region-encoding-and-save-integrity.md) |
| Data root | The per-user directory holding campaigns, world packages, and set packages: the local application data folder plus `SpaceExplorer`, overridable by `SPACE_EXPLORER_DATA_DIR`. Caches live under a separate cache root. | [Storage location](technical-design.md#storage-location-and-layout), [decision 0018](decisions/0018-data-root-region-encoding-and-save-integrity.md) |
| Reference index | The table in `<data root>/index.db` recording which campaigns, worlds, exports, and backups depend on each shared package or blob; maintained in the publish-last transaction, rebuildable from manifests, and the sole input of the explicit deletion sweep. | [Decision 0040](decisions/0040-reference-index-and-deletion-sweep.md) |
