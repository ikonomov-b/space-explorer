# 0031. Primitive-complete composition and adaptive storage

Date: 2026-09-07. Status: Accepted. Source: owner clarification of 2026-09-07. Supersedes the blanket terrain materialization of [decision 0001](0001-materialize-authoritative-terrain.md). Supersedes the fixed region encoding and world-package layout of [decision 0018](0018-data-root-region-encoding-and-save-integrity.md). Supersedes the revision-blind exact-reference contract of [decision 0029](0029-primitive-identity-handle-and-cross-package-set-operations-contract.md).

## Context

The project already requires stored primitive sets before world generation, but it did not say whether the primitive system merely supplies visible parts or represents the complete generated environment. It also treated materialized region data as a separate authoritative format, let `PrimitiveId` stand in for an exact revision inside `ReferenceTable`, and left material, texture, geometry, behaviour, caching, and mutable environmental state outside one coherent primitive contract.

The owner clarified that a generated solar system must be represented completely by randomly combined primitive IDs and their generated parameters: star type; planet count, type, orbit, and composition; terrain, water, relief, caves, valleys, rivers, vegetation and life; sites; and artifacts. There is no second environment-data model alongside the primitive graph. Exact old-world reproduction remains required, while expensive derived data may be cached and regeneration versus storage is decided from measurement.

## Decision

**Complete representation.** Every rendered, simulated, physical, biological, environmental, and collectable property originates in an exact primitive revision, its instance parameters, or a primitive-based mutable-state overlay. Manifests and graph records contain identity, topology, versioning, storage, and integrity metadata only; they cannot introduce environment properties independently. A primitive set is the reusable catalogue of definitions. A solar system, planet, surface, cave, life form, site, or artifact is a bounded ordered composition graph, not a mathematical set: nodes may repeat a definition and preserve parameters, transforms, connectors, and child order. Graphs may nest but are acyclic and have versioned depth, node-count, and work limits.

**Definitions and instances.** A definition has a stable `PrimitiveId`; exact use is `PrimitiveId` plus the definition content hash. A compatible revision of the same conceptual definition retains its ID and receives a new hash; a different concept receives a new ID. Every instance has a deterministic hierarchical path used for its random stream, persistent addressing, cross-chunk references, and cache keys. Numeric variation is stored as instance parameters bounded by the definition rather than allocated as a new primitive ID for each value.

Each definition has a category from a versioned numeric category registry; one or more composition domains such as solar system, planet, surface, cave, life form, site, and artifact; an engine-neutral geometry reference or recipe; required surface-material and optional texture primitive references; typed parameters; typed connectors; constraints; a storage policy; exact primitive and content-addressed asset dependencies; and provenance. Materials and texture recipes are reusable primitives. Appearance-affecting mesh and texture bytes are immutable content-addressed assets referenced through primitives; renderer-ready conversions are caches. Authored templates are separately identified, versioned generation inputs, not runtime primitives. Generated definitions record the exact template revisions that produced them.

**Deterministic types and combination.** Authoritative parameters use a closed schema of booleans, enums, signed and unsigned integers, fixed-point scalars/vectors/rotations/colours/bounds, exact primitive references, ordered arrays, bounded grids, and content hashes. Authoritative floating point, arbitrary JSON objects, unordered maps, and engine-native types are forbidden. Compatibility is not a group-name equality check: composition domains provide the broad boundary, while typed connectors define role or direction, cardinality, attachment transform or spatial area, required and excluded tags, and parameter constraints. Versioned grammar rules define eligible categories, integer weights, required and optional children, counts, semantic constraints, retry budgets, and fallbacks. Composed values use explicit versioned aggregation-rule primitives rather than implicit insertion order. An unoccupied optional connector represents structural absence; meaningful absence, such as an airless atmosphere, is an explicit primitive. Zero remains an invalid primitive ID.

Geometry may be a deterministic procedural recipe or a content-addressed mesh dependency. Visual geometry, authoritative collision, navigation/traversal, physical properties, simulation behaviour, and aggregation rules are separate primitive references. Packages are data-only: they contain no C#, GDScript, native code, or unrestricted shader source. Materials select approved versioned shader templates with bounded parameters; mesh, image, graph, and decompressed sizes are validated before allocation or use. Canonical readers reject truncated, overflowing, non-minimal, trailing, and over-budget encodings so one semantic record cannot acquire several accepted byte representations.

**Storage and caching.** Each definition pins one of three policies selected by cross-platform determinism and performance measurements: `regenerate` stores the exact graph inputs and retains the required generator implementation; `materialize` stores the accepted output as a primitive-owned payload; `hybrid` stores a compact authoritative result and regenerates higher-detail output. Materialized data is still a parameter or payload of a primitive instance, never a separate region model. A category may use regeneration only when it reproduces exactly and background work reliably stays ahead of exploration; inability to prove exact reproduction selects materialization. Actual time, memory, and disk thresholds remain measured, versioned configuration until a later decision freezes them.

Large graphs are partitioned into deterministic spatial chunks. Each instance has one owning chunk; cross-chunk edges use stable instance paths; one chunk never consumes another's random stream. Active chunks use a memory cache and expensive derived meshes, textures, collision products, and other render/runtime products use a size-limited disk cache. Both caches are fully evictable and must reconstruct exactly from authoritative primitive data. Cache keys include world identity, exact primitive revisions, parameters, generator and grammar versions, chunk identity, and level of detail.

The generated world is an immutable base graph. Discoveries, collection, damage, depletion, and other persistent changes are primitive-based overlay records keyed by stable instance path. Loading or regeneration constructs the base and then applies the overlay; it never rewrites a content-addressed base package. Overlay records participate in the campaign transaction and integrity-tag rules rather than becoming unverified cache state.

**Packages, lookup, and synchronization.** One primitive-set generation run publishes one immutable pack with IDs `1..n`, its specification, accepted definitions, composition rules, exact template/base-pack/asset dependencies, and validation result. Canonical package files are authoritative; SQLite indexes verified immutable content and stores transactional campaign overlays. Publication writes and verifies files first and commits index references last. Old revisions and generator implementations remain available while referenced; content may be retired from new generation but is deleted only when no campaign, world, export, or retained backup depends on it. Missing exact content is an explicit compatibility error, never a substitution.

Reference tables and dependency sets map handles to exact revision references (`PrimitiveId` plus content hash), not to `PrimitiveId` alone. Set operations across packs or revisions likewise operate on exact revision references. Multiplayer exchanges manifests and hashes first, reuses verified local blobs, obtains only missing data-only packages/assets, verifies them before use, and synchronizes mutable overlays separately. Exports carry the complete dependency closure.

## Consequences

Easier: one compositional model covers every scale, old systems cannot silently acquire current assets or rules, caches can save load time without becoming save data, and multiplayer can deduplicate immutable content by hash. Harder: M0a must define exact revision references, category and parameter schemas, connector and grammar validation, package bounds, and atomic publication before M0b; regeneration now requires retaining every referenced generator implementation; material/texture and behaviour composition need data-only interpreters in the game adapter; and the fixed region codec is no longer the universal authoritative representation.

The 2,048 m region bound and integer units remain. Decision 0017's 3 MiB raw height/biome calculation remains a benchmark fixture for a maximal materialized or hybrid terrain payload, but its 1 MiB result is now a measured storage target rather than a mandate that every region store that particular heightfield/biome representation. Decision 0018's data-root and save-integrity clauses remain unchanged.
