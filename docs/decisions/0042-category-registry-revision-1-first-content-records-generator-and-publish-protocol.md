# 0042. Category registry revision 1, the first content records, the set generator, and the publish protocol

Date: 2026-09-07. Status: Accepted. Source: implementation of the M0a immediate step under [decision 0031](0031-primitive-complete-composition-and-storage.md) and decisions [0033](0033-generated-definitions-have-one-revision.md) to [0041](0041-planet-fields-tangent-regions-minimum-radius-and-far-field.md); recorded because it freezes the first content formats, as [decision 0020](0020-canonical-encoding-and-content-hash.md) did for the encoding beneath them.

## Context

Decision 0035 requires a category registry record whose revision every definition label carries, decision 0033 fixes one hash per generated definition, decision 0034 keeps storage policy out of the definition, decisions 0036 to 0038 fix the transform, derivation, and derived-instance rules the registry must be able to express, and decision 0039 fixes one manifest per pack. None of these existed as bytes. [Decision 0030](0030-m0a-criterion-1-proceeds-before-the-p0-exit-record.md) accepted that every `pack_id` minted before the P0 exit record may be superseded, so this is the moment to freeze the first records rather than a later one.

## Decision

**Registry revision 1** is `CategoryRegistryRevision1.Registry` in `SpaceExplorer.Core.Registry`, defined in code and frozen by its recorded hash `1419038daa22a9b92629c4a7ebbef17902c8d63ddadf3727e6d40b98cea657fb`; moving its source form to `content/` waits for a second revision or an authoring tool, a trim of decision 0035's placement rather than a change to it. It defines nine categories: `star` (1), `barycentre` (2), `planet` (3), `atmosphere` (4), `surface-material` (5), `texture-recipe` (6), `geometry-recipe` (7), `artifact-part` (8), and `artifact` (9), the basic groups [decision 0030](0030-m0a-criterion-1-proceeds-before-the-p0-exit-record.md) named. Every category permits `materialize` only, lists no generator revision identifiers, and derives no instances. The closed schema admits eight parameter kinds: boolean, enum with labels, integer with optional fraction bits, binary turn, rotation, three-vector, RGBA colour, and exact primitive reference constrained to a category; grids and cube-sphere grids arrive with the first category that needs them. Connector kinds carry one of the three transform kinds of decision 0036; planet-fixed lengths use 8 fraction bits, artifact-local lengths 16; mass is in units of 10^20 kg and luminosity of 10^20 W. An explicit `airless` model is an enum value of `atmosphere`, so absence is a definition, as decision 0031 requires.

**Six record kinds** share the encoding of decision 0020 and reject trailing bytes and any non-canonical encoding by re-encoding and comparing. `category-registry/1` lists the categories in ascending ID order. `primitive-definition/1/registry/1` holds the category, the provenance (kind, template pack, template ID, template hash), the parameter values in schema order, one tag declaration per connector kind, and the generator revision text, empty for none; it carries no identity, so identical content is one file however many packs hold it, and the manifest binds a local ID to its hash. A set holds each content hash once; the generator rejects a duplicate. `primitive-template/1/registry/1` holds a template's ID, label, category, a bounded range per parameter, and its connector declarations; its hash is the exact template revision. `template-vocabulary/1/registry/1` holds the authored pack identifier and the templates inline in ascending ID order. `set-specification/1` holds the registry revision and hash, the generator version, grammar version 1, the seed, the template pack and vocabulary hash, the requests in order, and the retry budget; the generated `pack_id` is the leading 16 bytes of its hash. `set-manifest/1` holds the specification hash, the pack, the registry revision and hash, the generator and grammar versions, the template pack and vocabulary hash, every definition as local ID, category, and hash in order 1..n, the generator revisions and storage-policy pins used, both empty in revision 1, and the validation result.

**Generation.** For request `r` of template `t`, instance `k` draws from the stream at path `set/template/<t>/instance/<k>` ([decision 0021](0021-sha256-stream-derivation.md)). Each parameter is sampled in schema order inside the template's range: enum indices and bounded integers by `Pcg32.NextBounded`, spans beyond 32 bits by two draws and rejection on the same threshold rule, and a reference uniformly from the definitions of the referenced category generated so far in the set. A duplicate content hash is rejected and redrawn within the retry budget; exhausting it, or needing a reference no earlier definition supplies, fails with an explicit `GenerationException`, and nothing is published. IDs are 1..n in generation order.

**Publication and loading.** `<data root>/index.db` holds `packages` with a uniqueness constraint on `pack_id`, `records`, and `dependants`, as decisions [0039](0039-one-manifest-per-pack-identifier.md) and [0040](0040-reference-index-and-deletion-sweep.md) require. Publishing first consults the index: the same manifest hash is an idempotent no-op, a different one is a `ReproductionFailureException` before any byte is written. Leftover `.tmp` files are removed, then each record is written to `<hash>.bin.tmp`, flushed to disk, re-read, verified, and moved into place without overwriting different content, and the index rows, including the edge from the pack to its template vocabulary, are committed in one transaction last. Loading reads the manifest hash from the index, verifies every record against its name before decoding it, refuses a manifest that pins another registry revision or hash with a `CompatibilityException`, and checks the definitions against the manifest and each other.

**Authoring.** A vocabulary's source form is `content/templates/<name>/vocabulary.json`, read by the command-line tool into the canonical record, which is the authority; a missing parameter takes its descriptor's full range. The first vocabulary is `basic`, eleven templates over eight categories, under an authored pack identifier drawn once outside the core. The authored allocation ledger of [decision 0006](0006-pack-identity-and-allocation.md) is not yet persisted; template IDs are checked ascending and distinct.

**Recorded vectors.** The registry hash above; the manifest hash `704ecc02107fc478cd26048feb6f3943f4eb5e3681cebc49c994c3806a63677c` of the test fixture's five requests at seed 7; the `basic` vocabulary at seed 42 publishing 36 definitions under pack `3df8b86354ddbb53ee1a51fc2698ad24`. As with [decision 0019](0019-generator-version-1-frozen.md), these are this implementation's output and freeze it without independently proving it.

## Consequences

Easier: a set can be generated, published, reloaded, inspected, and validated without Godot; every later record kind has six worked examples of the label, bounds, and re-encoding rules; identical definitions across packs dedupe on disk. Harder: a change to any field order or to registry revision 1 supersedes every pack minted under them, which decision 0030 accepted for this window; the content gate still needs the Godot viewer to resolve these records.

Verified on the Debian 13 workstation: `dotnet build` with zero warnings; 161 Core and 11 Persistence tests pass. Mutation-checked on four rules, each of which turns the suite red: a reference table keying duplicates by exact reference, the generator accepting duplicate content, the loader skipping the record hash check, and the publisher accepting a differing manifest. The CLI publishes the `basic` vocabulary at seed 42 as 37 records, reloads and validates them, republishes as a no-op, and refuses a corrupted record. Not verified: the same hashes on `windows-latest`, which the continuous-integration run for this commit supplies; a two-process comparison, now possible through `generate-set` but not yet in the suite; the content gate.
